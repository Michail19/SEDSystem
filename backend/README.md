# Сервер SEDSystem

Java 21, Spring Boot, Spring Security, Spring JDBC и PostgreSQL. REST API расположен под `/api`; для демонстрации используется HTTP Basic и шесть локальных учётных записей. Проверки роли и состояния выполняются на сервере. Пароли хешируются в памяти при запуске; значение `DEMO_PASSWORD` общее для учебных пользователей. Это не промышленная схема идентификации.

## Запуск

Предпочтительный способ — `docker compose up --build` из корня репозитория. Для запуска вне Docker нужны Java 21, Maven и PostgreSQL:

```bash
mvn spring-boot:run
mvn verify
```

По умолчанию сервер подключается к `jdbc:postgresql://localhost:5432/sed` с пользователем и паролем `sed`. Настройки: `DATABASE_URL`, `DATABASE_USER`, `DATABASE_PASSWORD`, `DEMO_PASSWORD`, `CORS_ORIGIN`. Схема создаётся при старте из `src/main/resources/schema.sql`; автоматических миграций существующей схемы пока нет.

Сущности: заявки, процедуры, предложения, результаты, договоры, версии документов, согласования и уведомления. Ключевые пути API: `/api/me`, `/api/requests`, `/api/procedures`, `/api/offers`, `/api/results`, `/api/contracts`, `/api/notifications`. Действия реализованы POST-запросами к карточкам. Данные файла сохраняются в PostgreSQL; скачивание разрешено внутренним ролям. Результат ЭДО — только демонстрационная запись.

При ожидании уточнения срок — пять календарных суток; планировщик раз в минуту закрывает просроченные предложения и создаёт уведомление. При остановленном сервере обработка выполняется после следующего запуска. Для изменения существующих таблиц потребуется добавить управляемые миграции.

Необязательная загрузка учебных данных из `demo-data.sql` описана в общем README. Скрипт добавляет данные один раз и не меняет существующие записи.
