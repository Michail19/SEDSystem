# SEDSystem — управление закупками и договорами

Учебный MVP клиент-серверной системы для курсовой работы. Система демонстрирует путь от заявки на закупку и рассмотрения предложений до согласования и исполнения договора. Используйте **только вымышленные данные**: это демонстрационное приложение, не предназначенное для производственной эксплуатации и юридически значимого документооборота.

## Архитектура

- `frontend/` — React и Vite: веб-интерфейс.
- `backend/` — Java 21 и Spring Boot: REST API, роли и правила процессов.
- PostgreSQL — сохранение предметных данных и файлов договора.
- Docker Compose — локальный запуск трёх уровней; GitHub Actions — сборка и тесты.

Дополнительные инструкции: [сервер](backend/README.md) и [клиент](frontend/README.md).

## Быстрый запуск

Нужен Docker с Compose. В корне репозитория:

```bash
docker compose up --build
```

Откройте http://localhost:5173. Клиент обращается к API через `/api` на том же адресе; Nginx перенаправляет запросы серверу внутри Compose. Сервер также доступен напрямую на http://localhost:8080, база данных хранится в Docker volume `postgres_data`. Остановить контейнеры: `docker compose down`. Команда `docker compose down -v` также удаляет учебные данные.

Для демонстрации доступны учётные записи `initiator`, `buyer`, `contractor`, `manager`, `supplier1`, `supplier2`; у всех пароль по умолчанию `demo123`. В форме входа роль выбирается из списка. При необходимости задайте переменные в `.env`: `DEMO_PASSWORD` и `DATABASE_PASSWORD`; см. `.env.example`. Это общий пароль демонстрационных аккаунтов, не корпоративная аутентификация.

## Демонстрационные данные

После запуска приложения можно по желанию добавить готовый набор вымышленных данных:

```bash
docker compose exec -T db psql -v ON_ERROR_STOP=1 -U sed -d sed -f /opt/sed/demo-data.sql
```

В наборе есть заявки в черновике, на согласовании и на доработке; открытые закупки с предложениями разных поставщиков и разными решениями; завершённые закупки и договоры на разных этапах. В некоторых договорах приложены учебные текстовые документы. Даты задаются относительно дня загрузки, чтобы открытые процедуры не оказались просроченными сразу после установки.

Команда добавляет записи к существующим данным, не удаляет и не заменяет их. Повторный запуск не создаёт дубликатов и не восстанавливает демонстрационные записи, которые были изменены или удалены после первой загрузки. Для автоматической проверки команда запускается только на чистой учебной БД CI.

## Сценарий демонстрации

1. `initiator`: создайте заявку и отправьте на согласование. `manager`: согласуйте её или верните с комментарием.
2. `buyer`: создайте процедуру из согласованной заявки. `supplier1` и `supplier2`: подайте предложения.
3. `buyer`: запросите уточнение, отклоните предложение с причиной или направьте решение о допуске руководителю. Поставщик может ответить на запрос; `manager` согласует допуск или возвращает решение на доработку. Отсутствие ответа в течение пяти календарных суток закрывает предложение автоматически; проверка выполняется раз в минуту. Уведомления отображаются поставщику внутри приложения.
4. `buyer`: после рассмотрения всех предложений выберите одно допущенное либо завершите процедуру без победителя.
5. `contractor`: создайте договор по успешному результату, загрузите документ и направьте на согласование. `manager` согласует документ или вернёт на доработку. История решений привязана к версии загруженного файла.
6. `contractor`: имитируйте передачу в ЭДО, зафиксируйте заключение, внесите сведения об исполнении и закройте договор.

Инициатор может изменить заявку до создания закупки: если она уже отправлена или согласована, она вернётся в черновик и потребует повторного согласования. Специалист по закупкам может изменить условия и срок открытой процедуры; изменение названия или условий возвращает все предложения на рассмотрение, а изменение только срока сохраняет решения. До конца срока подачи поставщик может изменить и повторно отправить своё предложение: оно вернётся на рассмотрение, прежний допуск будет отменён. После завершения процедуры такие изменения недоступны. Бюджет заявки после создания процедуры не меняется.

Руководитель может вернуть согласованную заявку на доработку до создания процедуры и отозвать допуск предложения до фиксации результата. Специалист по договорам может отозвать договор с согласования или после согласования для исправления; руководитель также может вернуть согласованный договор. Это доступно до имитации передачи в ЭДО. Решения и отзыв договора сохраняются в истории с автором, комментарием и версией документа; для заявок и предложений хранится текущее решение и комментарий, полной истории изменений нет.

Карточки показывают текущие состояния; кнопки зависят от роли и статуса. Сервер самостоятельно проверяет права и допустимость переходов.

## Объём и ограничения

Одна процедура на заявку, один победитель и один договор на результат; поставщики — две заранее созданные учебные учётные записи. Учётные записи находятся в конфигурации сервера, а не во внешнем корпоративном каталоге. ЭДО **имитируется**: реальный обмен, ЭП и юридическое заключение не выполняются. Договорные файлы хранятся в PostgreSQL, размер до 10 МБ; согласование привязывается к последней загруженной версии. Уведомления только внутри системы. Реальной отправки писем, ERP, оплаты, многопользовательского администрирования и резервного копирования нет. При публичном развёртывании используйте HTTPS и только тестовые данные.

Предварительные показатели из работы (p95, 10 RPS, доступность) не подтверждены самим фактом реализации: нужны отдельные измерения и мониторинг. Учебный стенд не является заменой корпоративному решению.

## Публикация

Можно развернуть PostgreSQL и Docker-сервис сервера на Render, а клиент как Static Site. Серверу нужны `DATABASE_URL` в формате JDBC (`jdbc:postgresql://host:port/database`), `DATABASE_USER`, `DATABASE_PASSWORD`, `DEMO_PASSWORD`, `CORS_ORIGIN` (точный HTTPS-адрес клиента). Клиент собирается с `VITE_API_URL=https://адрес-сервера/api`. На Render для Docker-сервиса укажите корневую директорию `backend`, для статического сайта — `frontend`, команду сборки `npm install && npm run build`, каталог публикации `dist`. Условия тарифов и доступность постоянной БД уточняются при развёртывании. Автодеплой и реальные облачные ресурсы не создаются этим репозиторием.
